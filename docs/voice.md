# Voice

Anchor for every text a user gets to see: interface, mails, error messages.

## Tone

Friendly, concrete, informal address. Fresh rather than corporate. Short sentences.

That is not decoration: these screens double as the demos the product is shown with. Whoever uses
them should enjoy it — otherwise no value materialises either.

## Anchors

- **Say what to do**, not what happened: "Confirm your address in it" rather than "A confirmation
  mail has been sent."
- **Bold the one thing that matters, nothing else** — "The link is valid for **one day**." Two
  emphases in a paragraph cancel each other out.
- **Error messages name the next step**, not the diagnosis: "Please reload the page and try again"
  rather than "The security check failed."
- **Stay industry-neutral.** The same sentence appears at a diving school, a nursing academy and
  an iSAQB training. The *tone* may be the same everywhere; the *content* must not assume a
  particular kind of provider.

## Don'ts

- No filler ("Your security matters to us")
- No blame on the user ("You forgot…", "Invalid input")
- No formal address; the informal form holds everywhere, error messages included
- No invented numbers or promises
- German texts use `ä ö ü ß`, never `ae oe ue ss` — that applies to texts, not to code comments
